多学科学习助手 · 全功能说明文档

一个以 RAG（检索增强生成） 为核心的多学科学习平台。

后端 FastAPI + 多语言向量检索（FAISS + sentence-transformers），前端纯 JavaScript 单页应用，LLM 由 DeepSeek（deepseek-chat）驱动。

本文档覆盖平台的全部功能，并阐明贯穿其中的学习闭环机制。

🔁 自我强化学习闭环 🧩 多专科助手 🔍 RAG 溯源对话 📝 智能测验 🧠 可生长思维导图 ⏰ 间隔重复复习 🔥 连续打卡正反馈

1核心学习循环机制

平台不是孤立功能的堆砌，而是围绕一条连续自我强化的学习闭环设计。四个环节首尾相接，每一环的产出自动成为下一环的输入：

        ┌─────────────────────────────────────────────────────┐
        │                                                     │
        ▼                                                     │
   ① 提问与解答  ───►  ② 测验与巩固  ───►  ③ 思维导图 / 知识结构化
   (RAG 对话)         (生成 + 评分)         (可编辑、可提问、可复习)
        ▲                  │                       │
        │                  │ 错题自动入库            │ 节点一键入库
        │                  ▼                       ▼
        └──────────  ④ 复习与连续正反馈  ◄───────────┘
                    (间隔重复 + 打卡连击)

闭环如何自我驱动

环节产出自动流向下一环
① 提问与解答对话中的疑难点任意回答可「加入复习」生成卡片
② 测验与巩固答错的题目错题自动注册为复习项（评分时即时入库）
③ 思维导图结构化知识节点节点可「加入复习」、可「学习此节点」回到对话
④ 复习与连续正反馈复习成绩反馈调整下次间隔；打卡连击形成正反馈，驱动学习者回到 ① 继续提问

正反馈的两条强化路径

1. 效果强化（间隔重复） — 复习引擎根据答题表现动态调整下次复习时间：答对则间隔 ×2.5 拉长，答错则重置为 1 天。错题反复回流直到掌握，确保学过的不忘。

2. 行为强化（连续打卡） — 每日学习活动累计为「连续天数」（streak），中断即归零。🔥 连击数 + 28 天活跃热力图给予可见的即时正反馈，驱动学习者每天回到循环。

这套机制把「知识结构化」彻底融入学习过程——思维导图不是静态产物，而是可编辑、可提问、可复习的活节点，远超 NotebookLM 的只读静态导图。

2学习助手层

平台内置 4 个专科助手，并支持运行时动态创建与删除任意数量的自定义助手。每个助手拥有完全隔离的知识库、会话历史、测验、思维导图、复习队列与备忘。

2.1 内置助手

数据结构与算法
data_structures · cpp

C++ 线性结构、栈队列、树、图、堆、哈希、排序查找、DP、贪心、回溯

计算机系统
computer_systems · c

计算机组成、操作系统、体系结构、汇编、编译、网络

离散数学
discrete_math · text

逻辑、集合、图论、组合、代数结构、数论、自动机

机器学习
machine_learning · python

监督/无监督/强化学习、深度学习、模型评估、NLP、CV

2.2 创建助手

入口：助手选择页「+ 创建助手」按钮（#createAssistantBtn）→ 模态框填写名称（≤30 字）与描述（≤200 字）。

后端 POST /api/assistants/create：

  • 生成唯一 ID：{名称slug}_{6位uuid}
  • 从 10 色调色板 + 10 图标库随机分配外观
  • 调用 build_generic_system_prompt(name, description) 自动生成专属系统提示词
  • 配置持久化至 data/assistants_config.json，并即时注册到全局助手表

新助手立即可用，拥有全套独立工作室功能。

2.3 删除助手

入口：助手卡片上的删除按钮（.card-delete-btn），二次确认。后端 POST /api/assistants/delete：级联清除该助手的全部数据——向量库、上传文件、会话、思维导图、复习项、测验历史、备忘。不可恢复。

2.4 提示词调优（Cursor 模版风格）

  • 系统提示词采用分层结构：通用教学基座模板（rag_engine.py 基座）+ 学科专属规则块。
  • 提示词工程借鉴主流 Coding Agent（如 Cursor）提示词模版的设计范式——明确角色、强约束输出格式、引用溯源、分步教学、苏格拉底式追问限额——以此保障回答的稳定性与教学质量（详见 第 6 节）。
  • 自定义助手通过名称 + 描述自动套用通用调优模板；专科助手则使用手工精调的学科模板。

3资料上传层

3.1 多文件拖拽统一上传

  • 拖拽区 #uploadZone：支持点击选择或拖拽放入。
  • 批量多文件：一次可拖入任意数量文件，按钮实时显示「上传 N 个文件」，通过单次 FormData 统一提交（POST /api/upload，字段 files 多值）。
  • 上传后逐文件回显结果（✓ 成功 / ✗ 失败）与切片数，状态如「完成: 3 成功, 1 失败」。
  • 上传前做扩展名校验。

支持格式

文本/代码：.txt .md .py .c .cpp .h .hpp
文档：.docx .pdf

3.2 自带多语言小模型执行切片

文件入库由 file_processor.py 完成，无需外部 API，本地即可切片：

  1. 解析：按格式提取纯文本（PDF / DOCX / 纯文本）。
  2. 混合分词：中文 → jieba 分词；代码块（以 ``` 或 ` 界定）→ 空白切分。
  3. 切片：CHUNK_SIZE = 512 token，CHUNK_OVERLAP = 64 token；切片边界对齐句子/换行（中文 。！？，英文 .!?），避免语义截断。
  4. 嵌入：共享多语言小模型 paraphrase-multilingual-MiniLM-L12-v2（启动时加载一次，全助手复用）将切片向量化。
  5. 索引：写入 FAISS 向量库（IndexIDMap(IndexFlatIP)，L2 归一化即余弦相似度），元数据（原始文件名、chunk_id）随存。
磁盘文件以 UUID 命名防冲突；原始文件名仅保存在 FAISS 元数据中。每个助手独立向量库位于 data/vector_store/{assistant_id}/。

3.3 文件管理

GET /api/files 列出已上传文件及元数据；DELETE /api/files/{file_uuid} 删除单文件；POST /api/kb/clear 清空整个知识库。

4提问与解答（RAG 对话引擎）

学习闭环的入口环节。

4.1 RAG 检索流程

用户提问→ 向量检索 top-5 切片→ 构建带溯源上下文 ≤4000 字→ 拼接系统提示词 + 历史→ DeepSeek 流式生成→ SSE 推送
  • 检索：top_k = 5，上下文上限 4000 字符，按句界截断。
  • 上下文格式带来源标注：参考片段 N: ... [来源: 文件名]，回答可溯源、防杜撰。
  • LLM：deepseek-chat，temperature=0.7，max_tokens=4096，SSE 流式输出（POST /api/chat）。

4.2 多会话管理

  • 每助手支持多会话，独立持久化（data/sessions/{assistant_id}/）。
  • 会话标题自动从首条用户消息提炼；支持新建、重命名、删除。
  • GET/POST /api/sessions、PATCH/DELETE /api/sessions/{id}。

4.3 历史预算与裁剪

token_budget.py：会话历史按 DEFAULT_HISTORY_BUDGET = 6000 token 预算，从最新向最旧保留，始终至少保留最近一条，防止上下文溢出。

4.4 消息级操作

  • 删除消息对：成对删除用户+助手回合，保持配对完整（DELETE /api/sessions/{id}/messages/{index}）。
  • 重新生成：对最后一轮重新流式生成（POST /api/sessions/{id}/regenerate）。
  • 加入复习：任意回答一键生成复习卡片，接入闭环（见 5.3）。

5工作室层 · 五大模块

工作室（#studioPanel）聚合测验、思维导图、复习、统计、备忘五大模块，构成完整学习链条。

5.1 测验与巩固

生成（POST /api/quiz/generate）

  • 题型：single_choice（单选）、short_answer（简答）、code_reading（读码）、proof（证明），可选「混合」。
  • 参数：数量 1–30、难度（easy/medium/hard）、主题（可选）。
  • 基于知识库出题：检索 top_k = 8、上下文上限 5000 字符，题目附带知识点与来源文件；知识库为空时回退到学科通用知识出题。
  • LLM：deepseek-chat，temperature=0.6，仅输出可解析 JSON。

评分（POST /api/quiz/grade）

  • 单选：本地按 A/B/C/D 字母精确匹配，0 或 1 分，不耗 LLM。
  • 简答/读码/证明：第二次 LLM 调用评分（temperature=0.2，「严格但鼓励」的助教），分值 ∈ {0, 0.5, 1}，附反馈。
  • 总分 = 各题之和，满分 = 题数。
  • 闭环关键：评分时错题自动注册为复习项（source.type = "quiz_wrong"），无缝进入复习队列。
  • 每次测验结果记入 quiz_history（日期、得分、题数、难度），供统计图表使用。

前端展示：逐题状态图标（✓/✗/△）、用户答案、参考答案、反馈；得分卡显示百分比与「总分 X / Y」。

5.2 思维导图与知识结构化

基于 jsmind 的可编辑、可生长、可提问、可复习的活导图——这是平台超越 NotebookLM 静态导图的核心。

AI 生成与生长（流式）

  • 生成整树 POST /api/mindmaps/ai/generate-tree：输入主题、深度（1–3）、宽度（2–8），流式生成 Markdown 树并实时渲染。
  • 扩展节点 POST /api/mindmaps/ai/expand-node：对任一节点 AI 扩展子节点（默认 4 个，参考兄弟节点上下文）。
  • 生成笔记 POST /api/mindmaps/ai/generate-note：为节点流式生成讲解笔记，存入 node.data.note。
  • 节点上限 500，支持中途取消（AbortController）。

节点级交互（右键菜单）

操作作用闭环连接
学习此节点将子树 Markdown 送入对话→ 回到提问解答
AI 扩展流式生成子节点知识自生长
AI 生成笔记 / 查看编辑笔记节点附带可编辑笔记结构化沉淀
重命名 / 添加子节点 / 删除子树手动编辑结构自主掌控
加入复习由节点生成复习卡片→ 接入复习闭环

编辑与持久化

  • 全程可手动编辑节点；编辑后 2 秒防抖自动保存，状态徽标显示「已保存 / 未保存 / 保存中 / 保存失败重试」。
  • 多导图管理：新建（空白或 AI）、加载、删除（GET/POST /api/mindmaps、PUT/DELETE /api/mindmaps/{id}）。
  • 支持导出 Markdown / 复制到剪贴板。
  • 存储：jsmind 标准 JSON，每助手独立（mindmap_store.py）。
对比 NotebookLM：NotebookLM 的思维导图只读、静态、不可交互。本平台导图可编辑结构、可对节点提问回到对话、可把节点送入复习——把「知识结构化」从结果变成持续进行的学习动作。

5.3 复习与间隔重复

review_engine.py 实现 SM-2 风格间隔重复（SRS），是「效果正反馈」的引擎。

复习项来源（三种类型）

  • mcq（单选）、qa（问答）、card（闪卡）。
  • 来源：测验错题（自动）、对话回答、思维导图节点（手动「加入复习」）。
  • 每项存快照 {front, back, answer_key, explanation}——即使原始内容删除仍可复习。

间隔调度算法

  • 初始：MCQ/QA 信号 0.5 → 间隔 2 天；其余 → 当天。
  • 答对（score ≥ 1.0）：新间隔 = max(1, round(当前间隔 × 2.5))——指数拉长。
  • 答错（score < 1.0）：新间隔 = 1——重置次日再练。
  • 记录 interval_days / ease(2.5) / next_review / review_count / last_grade。

今日队列（GET /api/reviews/queue/today）

  • 取所有 next_review ≤ 今日 的活跃项，每日上限 20。
  • 优先级排序：测验 0 分错题 > 0.5 分 > 其他错题 > 其余；再按逾期天数、来源权重、创建时间排序。

复习评分（POST /api/reviews/{id}/grade）

  • MCQ：字母精确匹配。
  • QA：有 API key 与作答时 LLM 评分，否则回退 0.5。
  • Card：自评。
  • 任意类型均可自评覆盖：不会→0.0 / 模糊→0.5 / 会→1.0。

前端流程：今日/全部双标签；闪卡「查看答案」翻面；自评三按钮；评分后显示反馈与参考答案并自动跳下一条；全部完成显示汇总「今天完成 X · 答对 Y · 模糊 Z · 答错 W」。

5.4 学习统计与连续正反馈

user_stats.py + 统计面板（#statsView），是「行为正反馈」的引擎。

连续打卡（streak）

  • 每次学习活动按本地日期记录；连续次日 +1，中断归零，刷新历史最长。
  • 面板 🔥 显示当前连击与历史最长（#streakCurrent / #streakMax）。

活跃热力图

近 28 天活动密度，颜色分 0–4 级，悬停显示「日期: N 次活动」。

测验趋势

Chart.js 折线图展示历次测验得分（0–100%），数据来自 quiz_history；无记录显示空状态。

复习完成率

进度条 + 百分比 + 「已完成 X / Y 张」。

知识库概览

文件数、切片数、总 token（≥1000 显示为「1.5k」）。数据接口：GET /api/stats/user、GET /api/stats/dashboard/{assistant_id}、GET /api/stats。

可见的连击与热力图把抽象的「坚持」变成即时奖励，形成驱动学习者每日回到闭环的正反馈。

5.5 长期备忘

memory_store.py：每助手一份长期备忘笔记。

  • 纯文本，上限 8 KB（防止膨胀拖累提示词）。
  • 关键作用：备忘内容会自动前置注入系统提示词，让助手在所有对话/测验中持续记住学习者的偏好、薄弱点、长期目标。
  • 接口：GET /api/memory、PUT /api/memory。

6提示词工程与效果保障

所有 LLM 调用（对话、测验生成、主观评分、思维导图）均由精心设计的提示词模版驱动，其设计范式借鉴主流 Coding Agent（如 Cursor）提示词模版的工程实践，以保障输出稳定、可控、教学有效：

  • 强角色定义：每个助手有明确学科身份与教学职责。
  • 严格输出契约：测验/评分强制「只输出可被 json.loads 解析的 JSON」，解析器 _extract_json 兜底剥离 ```json 围栏并扫描最外层 {...}。
  • RAG 溯源优先：优先引用知识库片段并标注来源，无依据时明确说明，杜绝杜撰。
  • 分层教学结构：结论先行 → 解释 → 示例 → 拓展；Markdown + LaTeX 数学排版。
  • 节制的苏格拉底式追问：每轮至多一个开放追问，避免过度引导。
  • 学科精调块：四个内置助手各有专属规则（如计算机系统的分层讲解、离散数学的严格证明、机器学习的张量形状标注）。
这套工程化提示词是「效果保障」的基础——把通用 LLM 约束成稳定、可溯源、面向教学的专科助教。
